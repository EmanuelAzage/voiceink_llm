* **Decision correction, found by live-testing against the real API before trusting it**: Gemini's function-declaration `Schema` object rejects `additionalProperties` outright (HTTP 400 — "Unknown name additionalProperties: Cannot find field"), contradicting the original assumption in [decisions.md](decisions.md). Fixed by dropping the field from `cardJsonSchema`'s wire representation; `validateExtractedCard()` is the real `additionalProperties: false` enforcement point, not the schema sent over the wire. Worth remembering as a general lesson: don't ship a schema-format assumption for a third-party API without a live smoke test, even when the shape looks like standard OpenAPI/JSON Schema.
